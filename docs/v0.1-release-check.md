`streamlit run app.py`で起動し、外部処理を実行せず次を確認しました。

- Homeと4機能ページが起動する
- Sidebar labelに実装filenameが表示されない
- My Profileの保存済みprofile、job axes、experiencesが表示される
- Company Researchで複数企業を切り替えられる
- CompanyごとにSourceとSnapshotが分離して表示される
- Research AssistantでSource metadata、retrieved evidence、result historyを区別できる
- Selection Preparationで企業、就活軸、経験のinput groupが表示される
- 通常のnavigationだけではAI requestやWebpage retrievalが発生しない

AI実行、本文再取得、save、delete、adoptionはsmoke test中に操作していません。

## Safety / Responsible AI Check

- AIはbutton操作時のみ実行される
- Evidence-backed researchはselected Snapshotを1件以上要求する
- Source metadataを取得本文として扱わない
- unselected Source / Snapshot IDをAIが返した場合は結果を拒否する
- supporting excerptがselected Snapshot本文に存在しない場合は結果を拒否する
- insufficient fieldを推論で補完しないruleとvalidationがある
- truncated inputをresult limitationで開示するruleがある
- AI resultはCompany Researchを自動更新しない
- existing company fieldの置換には明示的なconfirmationがある
- Selection Preparationはscoreや最終回答として表示しない
- API keyとraw API exceptionを通常UIへ表示しない
- insufficient creditを専用の安全な日本語messageへ変換する

## Retrieval Safety Check

- HTTP / HTTPS only
- credential付きURLを拒否
- localhost / local / internal hostnameを拒否
- private / reserved / non-global IPを拒否
- redirect destinationを再検証
- redirect上限3回
- timeout 10秒
- response size上限2 MiB
- content typeをHTML/plain textに限定
- PDFを未対応として明示的に拒否
- proxy環境変数を使用しない
- exact / whitespace-normalized duplicate blockだけを保守的に除去

## Data Integrity Check

- SQLite foreign keysをconnectionごとに有効化
- initializationは複数回実行可能
- singleton `user_profile`を維持
- job axisの`display_order`をcreate/delete/move後に連続化
- company、source、snapshotのownership境界を検証
- company delete時のrelated dataはforeign-key cascadeに従う
- JSON textのdecode failureを安全に扱う
- timestampはstorageとJST displayを分離

## Known Limitations Accepted for v0.1

1. Local single-user applicationであり、認証・共有・同期はない
2. Static HTML / plain text以外のretrievalは限定的
3. Sourceの正確性・最新性・信頼性はユーザー確認が必要
4. Evidence-backed AIでも解釈誤りの可能性は残る
5. OpenAI API keyとcreditは利用者が用意する
6. UIはdesktop-firstであり、mobile専用最適化はしていない
7. Latest NewsはProduct Requirements上の構想だが、v0.1実装には含めていない
